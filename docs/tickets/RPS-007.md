# RPS-007 — Alur memilih slot dan konfirmasi booking

Status: **Belum dimulai**

Prioritas: **P0**

Dependensi: RPS-005, RPS-006

## Tujuan dan cakupan

Bangun alur pelanggan memilih unit/tanggal/durasi/jam, mengisi data dan mengonfirmasi
booking. Gunakan availability dan hasil server; jangan membangun kalender dengan data palsu.

## Kriteria penerimaan

- [ ] Unit dan tarif mudah dibandingkan; tanggal/horizon dan durasi mengikuti PRD.
- [ ] Slot membedakan tersedia, terisi, diblokir dan sudah lewat tanpa warna saja.
- [ ] Pilihan unit/tanggal/durasi baru membatalkan hasil fetch lama; respons terlambat
  tidak menimpa pilihan terbaru. Tidak bisa submit hasil slot yang belum selesai dimuat.
- [ ] Ringkasan memuat unit, waktu WIB, durasi dan quote; hasil akhir memakai total server.
- [ ] Form berlabel, nomor opsional, anjuran memakai data contoh, serta field error server.
- [ ] Submit dinonaktifkan saat berlangsung. Retry payload sama mempertahankan key;
  input booking berubah membuat key baru. Timeout tidak otomatis membuat request baru.
- [ ] Konflik 409 menjaga isian dan menyegarkan slot; loading/empty/error/retry jelas.
- [ ] Sukses menampilkan nomor reservasi, snapshot dan Bayar di tempat, tanpa label lunas.
- [ ] Navigasi/reset sesi tidak menampilkan response booking dari sesi sebelumnya.

## Verifikasi tanpa unit test

Coba alur D+1 PS5 A 19.00 selama 120 menit: total Rp50.000. Simulasikan koneksi lambat,
request gagal/timeout, pergantian tanggal cepat dan slot direbut request kedua. Periksa
keyboard, ponsel, serta database bahwa klik ganda/retry hanya membuat satu booking.

Untuk implementasi, `npm run check` harus lolos. Gunakan database/port sementara bila
relevan, periksa kembali [PRD](../../PRD.md) dan [aturan proyek](../../AGENTS.md).
Kerjakan tiket ini saja; fitur tiket berikutnya tidak otomatis ikut dikerjakan.
