# RPS-006 — Landing, arah visual dan kerangka frontend

Status: **Selesai**

Prioritas: **P0**

Dependensi: RPS-003, RPS-004

## Tujuan dan cakupan

Gunakan skill frontend-design untuk membuat arah visual Sesi Play dan landing bisnis.
Siapkan shell navigasi, pemulihan sesi, masuk/ganti peran, logout dan halaman tujuan.

## Acuan visual yang sudah disiapkan

Baca [DESIGN.md](../../DESIGN.md) dan [prototype tiga layar](../design/README.md).
Arah visual, token, HTML/CSS dan screenshot disiapkan terpisah dari aplikasi. Gunakan
sebagai acuan; hubungkan ke API sesuai PRD. Data prototype tidak boleh menjadi logika bisnis.
Implementasi mengikuti acuan ini; perbedaan karena data nyata dicatat di DESIGN.md §13.

## Kriteria penerimaan

- [x] Landing memperlihatkan identitas contoh, fasilitas, unit/tarif, jam buka,
  cara booking dan CTA pelanggan/pemilik. Tidak ada ulasan atau klaim bisnis palsu.
- [x] Arah tipografi, warna dan layout dicatat; tampilan matang, tidak penuh neon/dekorasi.
- [x] Landing tanpa sesi memuat katalog publik dan tidak membuat workspace otomatis.
- [x] CTA membuat sesi sesuai role, lalu menuju alur yang benar; ganti peran memakai
  workspace yang sama dengan penjelasan bahwa ini simulasi.
- [x] Refresh/deep link memulihkan sesi; loading, error, retry dan expiry terlihat jelas.
- [x] Navigasi sesuai role; proteksi server tetap berlaku pada request langsung.
- [x] Logout memakai konfirmasi bahwa data demo dihapus, lalu kembali ke landing.
- [x] Nyaman pada 360/768/1280px, keyboard dan reduced motion; tidak scroll horizontal.
- [x] Penjelasan demo, data sementara dan pembayaran di tempat terlihat sebelum mencoba.

## Verifikasi tanpa unit test

Jalankan build produksi di browser. Periksa landing tanpa cookie, kedua CTA, refresh,
role switch, logout, error API dan sesi habis. Periksa tiga ukuran layar dan fokus keyboard.
Halaman booking/agenda lengkap dikerjakan di tiket berikutnya.

Untuk implementasi, `npm run check` harus lolos. Gunakan database/port sementara bila

### Perubahan

- Landing (`pages/LandingPage.jsx`, `components/landing/*`): hero + CTA **Coba booking**,
  daftar penjelasan demo, papan jadwal ilustrasi berlabel, fasilitas + jam buka dari server,
  unit/tarif PS4/PS5 dari `GET /api/catalog`, cara booking 3 langkah, footer batas demo.
  Tanpa ulasan, alamat yang bisa didatangi, atau klaim bisnis/afiliasi.
- Sesi: `SessionProvider` memulihkan sesi via `GET /api/session` saat muat/refresh/deep link,
  CTA membuat sesi sesuai peran (`useDemoStart`), ganti peran di workspace sama dengan notice
  simulasi, logout dengan dialog konfirmasi lalu kembali ke landing, timer masa berlaku
  menampilkan "Ruang demo sudah berakhir." tanpa interaksi.
- Router History API kecil (`lib/router.js`, `lib/routes.js`), shell aplikasi dengan nav per
  peran, bar demo (masa berlaku WIB, data sementara, bayar di tempat), halaman tujuan
  booking/booking saya/agenda/unit/pengaturan (isi "sedang disiapkan" + unit workspace nyata).
- Layar status: memuat, gagal cek sesi (Coba lagi), belum masuk, sesi berakhir, peran tidak
  sesuai (ganti peran), 404. Skip link, fokus ke `<main>` saat pindah halaman (bukan saat muat
  awal), `aria-current`, dialog native dengan Escape/kembali fokus, reduced motion.
- CSS token/komponen (`styles/*`), font lokal + lisensi OFL di `client/public/fonts/`,
  `useHealth.js`/`styles.css` fondasi lama dihapus. DESIGN.md §13 mencatat implementasi.

### Temuan dan perbaikan selama uji

- Padding samping `.wrap` tertimpa `padding: … 0` di header/`main` aplikasi (konten menempel
  tepi di 360px) → diganti padding atas/bawah saja.
- Fokus dipindah ke `main` juga saat muat awal sehingga Tab pertama melewati skip link →
  kini hanya saat navigasi antarhalaman.
- Saat TTL habis, browser sudah membuang cookie (Expires = akhir workspace) sehingga server
  menjawab "tanpa sesi", bukan `SESSION_EXPIRED`; UI sempat menampilkan "Masuk demo dulu."
  → timer masa berlaku memperlakukan 401 sebagai sesi berakhir. Teks layar masuk juga
  menyebut kemungkinan ruang demo lama sudah berakhir.

### Batasan

- Pada implementasi awal RPS-006, semua halaman tujuan masih placeholder. RPS-007 kini
  mengimplementasikan booking; booking saya/agenda/unit/pengaturan tetap tiket berikutnya.
- Hanya Chromium headless; Firefox/Safari dan pembaca layar sungguhan belum diuji.
- Refresh setelah cookie kedaluwarsa dibuang browser menampilkan layar "Masuk demo dulu."
  dengan penjelasan umum, karena server tidak lagi menerima cookie untuk dikenali.
- Cek sesi anonim di landing menghasilkan 401 di console browser (perilaku API RPS-003).
