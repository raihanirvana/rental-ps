# RPS-002 — Database, migrasi dan seed relatif WIB

Status: **Selesai**

Prioritas: **P0**

Dependensi: RPS-001

## Tujuan dan cakupan

Buat skema SQLite, migrasi berversi dan seed per workspace. Pisahkan akses database,
repository dan pembuat data contoh. Siapkan model lengkap PRD tanpa membuat route bisnis.

## Kriteria penerimaan

- [x] Entitas workspace, sesi, pengaturan, unit, booking, booking_requests dan blok tersedia.
- [x] Foreign key aktif; relasi unit/booking/blok tidak bisa menyilang workspace.
- [x] Constraint melindungi enum, tarif integer, interval positif dan key unik per workspace.
- [x] Empat unit sesuai PRD; booking/blok relatif WIB, tidak bertabrakan, dan jelas sebagai seed.
- [x] Ada contoh confirmed, completed dan cancelled; snapshot unit/harga tidak bergantung
  pada perubahan unit. Seed selesai berada di masa lalu.
- [x] Migrasi/seed tidak menggandakan data ketika dijalankan ulang.
- [x] Kegagalan migrasi/seed tidak meninggalkan workspace separuh terisi.
- [x] Path database dikonfigurasi; health memeriksa database tanpa membocorkan path/rahasia.

## Verifikasi tanpa unit test

Gunakan file SQLite sementara. Jalankan migrasi dua kali, periksa jumlah dan integritas
relasi, lalu restart server untuk membuktikan data tersimpan. Coba INSERT relasi salah
serta rollback seed melalui harness sementara. Jangan menyentuh database pengembangan.

Untuk implementasi, `npm run check` harus lolos. Gunakan database/port sementara bila
relevan, periksa kembali [PRD](../../PRD.md) dan [aturan proyek](../../AGENTS.md).
Kerjakan tiket ini saja; fitur tiket berikutnya tidak otomatis ikut dikerjakan.

## Bukti penyelesaian

Diverifikasi 15 Oktober 2026 pukul ±14.50 WIB (D = 2026-10-15), Node 22.20.0, SQLite 3.50.4.
Semua uji memakai file SQLite di scratchpad (`DATABASE_PATH` sementara) dan port 4327;
folder `data/` proyek tidak dibuat atau disentuh.

### Perubahan

- `server/database/migrations/001_initial_schema.sql`: tabel `STRICT` `workspaces`
  (+`data_version`, `seeded_at`), `sessions`, `business_settings`, `units`, `bookings`,
  `booking_requests`, `unit_blocks`. FK komposit `(workspace_id, id)` untuk unit→booking/blok
  dan booking→request; CHECK enum, ISO UTC, tarif 1.000–1.000.000 integer, durasi 60/120/180,
  `total*60 = tarif*durasi`, jam buka WIB, kelipatan 30 menit, satu hari, konsistensi status,
  nomor HP 8–15 digit. Trigger: bentrok `[mulai, selesai)` booking/blok, jadwal booking dan blok
  tidak bisa diubah, status terminal, maksimal 20 unit per workspace.
- `server/database/connection.js` (WAL, FK, busy_timeout), `transaction.js`
  (`BEGIN IMMEDIATE`), `migrate.js` (berversi + checksum, satu transaksi per migrasi).
- Repository insert/baca: `workspace`, `settings`, `unit`, `booking`, `block`.
- Seed: `sample-catalog.js` (identitas fiktif, 4 unit PRD), `sample-schedule.js` (14 booking,
  2 blok relatif D-3…D+4), `build-records.js` (snapshot, status dari waktu server),
  `index.js` (`createSeededWorkspace` dalam satu transaksi, idempoten lewat `seeded_at`).
- `server/lib/wib-time.js`, `booking-reference.js` (`SP-XXXXXX`).
- `config.databasePath` (`DATABASE_PATH`), server memigrasi saat start, health cek database.
- `scripts/migrate.js`, `scripts/seed.js`, `npm run db:migrate` / `db:seed`, README, `.env.example`.

| Ubah jam booking; cancelled→confirmed; completed sebelum selesai | `BOOKING_IMMUTABLE` / `INVALID_STATUS_TRANSITION` / CHECK |

| Hapus workspace | Unit/booking/request/blok ikut terhapus; workspace lain tetap 14 booking; FK check 0 |
| Server start → health → stop, dua kali | 200 `database: connected`; data sama (14 booking, reference sama) setelah restart |
| Health dengan database tertutup | 503 `degraded/unavailable`, tanpa path atau pesan error mentah |

### Batasan

- Belum ada route bisnis; repository baru berisi insert/baca yang dipakai seed.
- Trigger hanya pengaman; pesan 409 dan pemeriksaan dalam transaksi dibuat di RPS-004/005.
  Konkurensi dua proses belum diuji (bagian RPS-005).
- `sessions` belum dipakai; pembuatan workspace per pengunjung, TTL dan pembersihan di RPS-003.
- Seed dijalankan di sekitar 14.50 WIB; status today (completed/confirmed) bergantung jam
  pembuatan, sesuai desain. Jika dibuat setelah 23.00, semua booking hari ini menjadi completed.
- Nomor booking acak 6 karakter; tabrakan sangat kecil tetapi akan menggagalkan seed secara
  utuh (rollback). Penanganan retry untuk booking pengunjung di RPS-005.
