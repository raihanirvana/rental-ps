# RPS-009 — Agenda pemilik dan penyelesaian sesi

Status: **Selesai**

Prioritas: **P0**

Dependensi: RPS-005, RPS-006

## Tujuan dan cakupan

Implementasikan GET owner agenda, PATCH status completed dan tampilan agenda harian.
Sertakan blok jadwal, detail booking, pembatalan dan ringkasan operasional yang jujur.

## Kriteria penerimaan

- [x] API/UI hanya owner; customer mendapat 403 meski memalsukan header/query role.
- [x] Filter tanggal/unit/status akurat; unit asing tidak membocorkan workspace lain.
- [x] Agenda menyertakan seed yang diberi penanda serta booking pengunjung dan blok.
- [x] Sesi berlangsung dihitung confirmed dengan mulai <= waktu server < selesai.
- [x] Jumlah booking, jam terjadwal dan nilai reservasi tidak menghitung cancelled;
  definisi ringkasan per filter terdokumentasi. Tidak ada klaim omzet/pembayaran diterima.
- [x] Completed hanya dari confirmed setelah selesai, diperiksa ulang dalam transaksi.
- [x] Cancel/complete bersamaan menghasilkan satu transisi sah; terminal tidak berubah.
- [x] Setelah mutasi, detail/agenda/ringkasan disegarkan; respons filter lama diabaikan.
- [x] Tampilan hari kosong, error/retry, blok, waktu WIB dan detail dapat dipahami di ponsel.

## Verifikasi tanpa unit test

Uji agenda dengan seed masa lalu/hari ini/mendatang, filter dan hitungan SQL. Coba
complete terlalu awal, sesudah akhir, status terminal serta cancel/complete bersamaan.
Verifikasi customer 403, ID asing 404, refresh browser dan akses keyboard.

Untuk implementasi, `npm run check` harus lolos. Gunakan database/port sementara bila
relevan, periksa kembali [PRD](../../PRD.md) dan [aturan proyek](../../AGENTS.md).
Kerjakan tiket ini saja; fitur tiket berikutnya tidak otomatis ikut dikerjakan.

## Bukti penyelesaian

Diverifikasi 15 Oktober 2026 ±17.20–17.35 WIB. API dengan curl/sqlite3 pada dua proses
server (port 4397/4398, file SQLite sementara yang sama); UI di Chromium 153 (Playwright dari
`~/ai-agent`) pada build produksi. Server dihentikan lewat PID sendiri. `npm run check` lolos.

### Perubahan

- `GET /api/owner/agenda?date=&unitId=&status=` (owner saja; semua parameter opsional,
  tanggal tidak dikirim = hari ini WIB server; kosong/parameter lain/ganda ditolak 400;
  unit asing 404).
  Respons: `serverTime`, `serverDate`, filter, semua unit workspace, booking tanggal itu
  (detail + `isSample`, `timeState`, `canCancel`, `canComplete`), blok, `summary`.
- **Definisi ringkasan:** dihitung dari booking yang tampil menurut filter tanggal/unit/status,
  **tanpa** booking cancelled. `bookingCount` jumlah booking; `ongoingCount` confirmed dengan
  mulai ≤ waktu server < selesai; `scheduledMinutes` jumlah durasi; `reservationValue` jumlah
  snapshot total (bukan pendapatan diterima). Filter status → blok tidak ditampilkan.
- `PATCH /api/owner/bookings/:id/status` body persis `{ "status": "completed" }`: dalam
  `BEGIN IMMEDIATE` (sesi diperiksa ulang) hanya confirmed yang `ends_at <= sekarang`; ulang
  completed → 200 `changed: false`; cancelled → 409 `INVALID_STATUS`; belum berakhir → 409
  `BOOKING_NOT_ENDED`; UPDATE juga dijaga `WHERE status='confirmed' AND ends_at <= now`.
  Pembatalan pemilik memakai `POST /api/bookings/:id/cancel` yang sudah ada.
- `withWorkspaceReadAccess` menerima daftar peran (agenda dibaca dalam snapshot dengan sesi
  owner terkini). File: `routes/owner.js`, `services/agenda-service.js`, `agenda-view.js`,
  `booking-status-service.js`, `repositories/agenda-repository.js`, `validation/agenda-validation.js`.
- UI `/pemilik` (`pages/AgendaPage.jsx`, `components/agenda/*`, `styles/agenda.css`):
  filter di URL, ringkasan + catatan nilai reservasi, timeline 10.00–23.00 (desktop) /
  daftar kronologis (ponsel), daftar booking dibatalkan, dialog detail booking/blok dengan
  Tandai selesai dan Batalkan (alasan opsional). Setelah mutasi: baris diganti respons server,
  agenda + ringkasan dimuat ulang di latar; respons filter lama diabaikan.
- `useModalDialog`: bila pemicu sudah hilang dari DOM, fokus kembali ke `<main>`.

### Temuan dan perbaikan selama uji

- Halaman agenda crash saat dimuat (`selected` null dibaca) dan dialog blok crash ("Invalid
  time value", item blok tanpa `kind`). Keduanya diperbaiki dan diuji ulang seluruh skenario.
- Setelah pembatalan, tombol pemicu keluar dari timeline sehingga fokus jatuh ke body;
  kini kembali ke `<main>`.
- Saya sempat menulis `eslint-disable-line` di `useAgenda`; diganti dependensi effect yang
  benar sebelum lint (aturan proyek melarang mematikan lint).

### Batasan

- Booking berlangsung/berakhir untuk uji dibuat langsung di DB (tidak bisa lewat API karena
  lead time). Penolakan PATCH di UI diuji dengan 409 diinjeksi; penolakan nyata lewat curl.
- Belum ada "Tambah booking" dari agenda; owner masih bisa membuat booking lewat API.
- Agenda menampilkan booking yang **mulai** pada tanggal itu dalam jam buka (sesuai aturan
  satu hari operasional).
- Hanya Chromium; Firefox/Safari dan pembaca layar sungguhan belum diuji.
