# RPS-003 — Sesi demo, peran dan isolasi workspace

Status: **Selesai**

Prioritas: **P0**

Dependensi: RPS-002

## Tujuan dan cakupan

Implementasikan POST demo sessions, GET session, DELETE session serta middleware
pemuatan sesi dan requireRole. Publik dapat mencoba customer/owner tanpa akun produksi.

## Kriteria penerimaan

- [x] Login baru membuat workspace, seed dan sesi secara atomik; body hanya menerima role.
- [x] Token acak hanya disimpan sebagai hash. Cookie HttpOnly, SameSite=Strict, Path=/api;
  Secure saat HTTPS melalui proxy terpercaya. Header proxy palsu tidak dipercaya.
- [x] Ganti peran mempertahankan workspace/TTL 12 jam dan mencabut token lama.
- [x] Sesi diperiksa ulang setelah kunci tulis untuk mutasi, termasuk ganti peran/logout.
- [x] Tanpa sesi/expired mendapat 401 yang jelas; cookie invalid dibersihkan.
- [x] Logout menghapus seluruh workspace sendiri dan cookie, serta aman diulang.
- [x] Workspace/role selalu berasal dari sesi; body, query atau header palsu tidak berwenang.
- [x] Dua cookie jar terisolasi; tab dengan cookie sama memakai workspace sama.
- [x] Cleanup workspace expired aman dan tidak menghapus workspace aktif.

## Verifikasi tanpa unit test

Gunakan curl dengan dua cookie jar, beberapa login paralel dan database sementara.
Periksa hash di database, token lama setelah ganti peran, logout, expiry dan restart.
Verifikasi atribut Secure memakai konfigurasi proxy terkontrol. Rate limit lengkap di RPS-012.

Untuk implementasi, `npm run check` harus lolos. Gunakan database/port sementara bila
relevan, periksa kembali [PRD](../../PRD.md) dan [aturan proyek](../../AGENTS.md).
Kerjakan tiket ini saja; fitur tiket berikutnya tidak otomatis ikut dikerjakan.

## Bukti penyelesaian

Diverifikasi 15 Oktober 2026 dengan Node 22.20.0, database SQLite sementara di scratchpad
dan port 4337–4339 (server proyek lain tidak dipakai). `npm run check` lolos.

### Perubahan

- `POST /api/demo/sessions` (body hanya `{ "role": "customer" | "owner" }`): tanpa sesi aktif
  membuat workspace + seed + sesi dalam satu `BEGIN IMMEDIATE` (201); dengan sesi aktif
  mengganti peran di workspace yang sama (200), masa berlaku tetap, token lama dicabut.
  Token yang sudah dicabut dan belum kedaluwarsa (mis. request ganti peran paralel) → 409 `SESSION_CHANGED`
  tanpa Set-Cookie dan tanpa workspace baru.
- `GET /api/session` (401 jelas, cookie invalid/expired dibersihkan; revoked tidak menimpa cookie baru) dan
  `DELETE /api/session` (204, menghapus workspace milik token aktif, aman diulang).
- Token `randomBytes(32)` base64url; database hanya menyimpan SHA-256. Cookie
  `sesi_play_session`: HttpOnly, SameSite=Strict, Path=/api, Expires = akhir workspace,
  Secure mengikuti `request.secure` dengan `TRUST_PROXY` (default false; `true` ditolak).
- `server/middleware/auth.js`: `loadSession`, `requireSession`, `requireRole`.
  `server/services/workspace-access.js`: `withWorkspaceAccess` untuk mutasi berikutnya
  (kunci tulis dulu, lalu sesi/peran diperiksa ulang).
- `server/services/session-resolver.js`, `demo-session-service.js`, `workspace-cleanup.js`
  (saat login + interval 10 menit, hanya `expires_at <= sekarang`),
  `repositories/session-repository.js`, `validation/session-validation.js`, `lib/session-cookie.js`.
- `Cache-Control: no-store` untuk seluruh `/api`. Config `DEMO_TTL_MINUTES` (720), `TRUST_PROXY`.
- `insertSeededWorkspace` dipisah dari `createSeededWorkspace` agar seed ikut transaksi login.

### Temuan dan perbaikan selama uji

- Ganti peran paralel awalnya membuat 5 workspace baru karena token yang baru dicabut
  dianggap "tanpa sesi". Diperbaiki dengan status `revoked` → 409; diuji ulang seperti di atas.
- Insiden pengujian: `pkill -f "node server/index.js"` ikut menghentikan server POS
  (`~/POS/seduh-pos`, port 51745) yang berjalan sejak 03.03. Tidak dinyalakan ulang karena
  konfigurasinya tidak diketahui; pemilik perlu menjalankannya kembali. Uji berikutnya hanya
  menghentikan PID yang dicatat sendiri.

### Batasan

- Origin check, rate limit 30 sesi/IP dan kapasitas 200 workspace dikerjakan di RPS-012.
  Saat ini pembuatan workspace tidak dibatasi.
- Belum ada UI; 409 `SESSION_CHANGED` perlu ditangani frontend (muat ulang sesi) di RPS-006.
- Konkurensi diuji dalam satu proses Node (permintaan diserialisasi oleh driver sinkron);
  pemeriksaan ulang setelah kunci dibuktikan lewat harness, bukan dua proses penulis.
- Secure diuji dengan header dari loopback, belum di balik proxy HTTPS sungguhan (RPS-013).

Review lanjutan memperbaiki respons revoked yang menghapus cookie baru, prioritas expiry
untuk token revoked, serta 503 DATABASE_BUSY. Uji ganti peran paralel, logout token lama,
restart dan expiry diulang. Rincian di [catatan review](../REVIEW-RPS-001-003.md).
