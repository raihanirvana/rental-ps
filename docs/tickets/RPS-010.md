# RPS-010 — Pengelolaan unit dan blok jadwal

Status: **Selesai**

Prioritas: **P0**

Dependensi: RPS-004, RPS-009

## Tujuan dan cakupan

Buat API dan UI owner untuk tambah/edit/nonaktifkan unit serta tambah/hapus blok.
Perubahan harus tetap aman ketika ada konfirmasi booking bersamaan.

## Kriteria penerimaan

- [x] Unit memiliki nama 2–40 karakter, jenis PS4/PS5, tarif integer Rp1.000–Rp1.000.000,
  status aktif; maksimal 20 unit per workspace. Validasi field asing konsisten.
- [x] Tidak menghapus unit fisik; nonaktif dengan booking non-cancelled yang belum
  berakhir ditolak 409. Pemeriksaan dan perubahan memakai transaksi yang sama.
- [x] Perubahan unit/harga tidak mengubah snapshot booking lama.
- [x] Blok mengikuti horizon, jam operasional dan grid 30 menit; boleh satu hari buka penuh.
  Awal blok tidak boleh lewat dan akhir harus setelah awal.
- [x] Blok menabrak booking non-cancelled atau blok lain ditolak 409 tanpa efek samping.
- [x] Request booking dan blok bersamaan tidak dapat sama-sama menguasai interval sama.
- [x] Hapus blok hanya workspace sendiri; slot dihitung ulang setelah perubahan.
- [x] Customer ditolak 403, ID asing 404; sesi diperiksa ulang setelah kunci tulis.
- [x] Form mempertahankan isian invalid; konfirmasi nonaktif/hapus dan error jelas.

## Verifikasi tanpa unit test

Uji API/UI untuk tarif string/pecahan, nama invalid, unit ke-21, perubahan snapshot,
nonaktif dengan booking mendatang, blok bertumpuk dan hapus. Kirim booking/blok bersamaan
serta booking/nonaktif bersamaan. Gunakan database sementara dan dua pengunjung.

Untuk implementasi, `npm run check` harus lolos. Gunakan database/port sementara bila
relevan, periksa kembali [PRD](../../PRD.md) dan [aturan proyek](../../AGENTS.md).
Kerjakan tiket ini saja; fitur tiket berikutnya tidak otomatis ikut dikerjakan.

## Bukti penyelesaian

Diverifikasi 15 Oktober 2026 ±18.10–18.25 WIB. API dengan curl/sqlite3 pada dua proses server
(port 4407/4408) dan satu file SQLite sementara; UI di Chromium 153 (Playwright dari `~/ai-agent`)
pada build produksi. Server dihentikan lewat PID sendiri. `npm run check` lolos.

### Perubahan

- API owner (`routes/owner.js`):
  - `GET /api/owner/units` → unit + `pendingBookings` (non-cancelled belum berakhir), `maxUnits`.
  - `POST /api/owner/units` (`name` 2–40 tanpa karakter kontrol, `kind` PS4/PS5, `hourlyRate`
    integer 1.000–1.000.000, `isActive` boolean opsional; field lain 400). Nama unik per
    workspace tanpa beda huruf besar (409 `UNIT_NAME_TAKEN`), maksimal 20 (409 `UNIT_LIMIT_REACHED`).
  - `PATCH /api/owner/units/:id` (subset field yang sama, minimal satu). Nonaktif dengan booking
    yang belum berakhir → 409 `UNIT_HAS_BOOKINGS`; pemeriksaan & update dalam transaksi yang sama.
    Unit tidak pernah dihapus fisik; snapshot booking tidak disentuh.
  - `GET /api/owner/blocks` → blok yang belum berakhir + `bookableDates`.
  - `POST /api/owner/blocks` (`unitId`, `date`, `startTime`, `endTime` grid 30 menit, `note` ≤120):
    horizon D…D+14, jam buka 10.00–23.00 (boleh sehari penuh), akhir > awal, awal tidak lewat;
    bentrok booking non-cancelled 409 `BLOCK_CONFLICT_BOOKING`, blok lain 409 `BLOCK_OVERLAP`.
  - `DELETE /api/owner/blocks/:id` → hanya workspace sendiri (404 selain itu).
  - Semua mutasi `withWorkspaceAccess` (BEGIN IMMEDIATE + sesi/peran diperiksa ulang).
    Trigger `UNIT_LIMIT_REACHED` dan unique nama dipetakan ke 409 sebagai pengaman terakhir.
- UI `/pemilik/unit` (`pages/UnitsPage.jsx`, `components/units/*`, `styles/units.css`): daftar unit
  dengan status dan jumlah booking belum berakhir, form tambah/ubah, dialog nonaktif, aktifkan,
  form blok (unit, tanggal, mulai/selesai, catatan), daftar blok mendatang, dialog hapus.
  Isian invalid dipertahankan; error server per field; daftar dimuat ulang setelah mutasi.
- Komponen bersama baru: `SelectField`, `FieldError`, `useAsyncAction`.

### Batasan

- Dua proses server yang dinyalakan **bersamaan** pada database baru: satu gagal start
  (`database is locked` saat mengaktifkan WAL ketika proses lain migrasi). Aplikasi dirancang
  satu instance penulis (PRD §11); uji konkurensi menyalakan proses kedua setelah yang pertama siap.
- Teks dialog hapus blok tidak tercatat oleh skrip (selektor menangkap dialog logout yang selalu
  ada di DOM); perilaku Kembali/Hapus terbukti.
- Unit dan blok tidak diedit "di tempat" untuk blok: ubah blok = hapus lalu buat ulang (sesuai PRD).
- Hanya Chromium; Firefox/Safari dan pembaca layar sungguhan belum diuji.
