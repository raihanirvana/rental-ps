# RPS-010 — Pengelolaan unit dan blok jadwal

Status: **Belum dimulai**

Prioritas: **P0**

Dependensi: RPS-004, RPS-009

## Tujuan dan cakupan

Buat API dan UI owner untuk tambah/edit/nonaktifkan unit serta tambah/hapus blok.
Perubahan harus tetap aman ketika ada konfirmasi booking bersamaan.

## Kriteria penerimaan

- [ ] Unit memiliki nama 2–40 karakter, jenis PS4/PS5, tarif integer Rp1.000–Rp1.000.000,
  status aktif; maksimal 20 unit per workspace. Validasi field asing konsisten.
- [ ] Tidak menghapus unit fisik; nonaktif dengan booking non-cancelled yang belum
  berakhir ditolak 409. Pemeriksaan dan perubahan memakai transaksi yang sama.
- [ ] Perubahan unit/harga tidak mengubah snapshot booking lama.
- [ ] Blok mengikuti horizon, jam operasional dan grid 30 menit; boleh satu hari buka penuh.
  Awal blok tidak boleh lewat dan akhir harus setelah awal.
- [ ] Blok menabrak booking non-cancelled atau blok lain ditolak 409 tanpa efek samping.
- [ ] Request booking dan blok bersamaan tidak dapat sama-sama menguasai interval sama.
- [ ] Hapus blok hanya workspace sendiri; slot dihitung ulang setelah perubahan.
- [ ] Customer ditolak 403, ID asing 404; sesi diperiksa ulang setelah kunci tulis.
- [ ] Form mempertahankan isian invalid; konfirmasi nonaktif/hapus dan error jelas.

## Verifikasi tanpa unit test

Uji API/UI untuk tarif string/pecahan, nama invalid, unit ke-21, perubahan snapshot,
nonaktif dengan booking mendatang, blok bertumpuk dan hapus. Kirim booking/blok bersamaan
serta booking/nonaktif bersamaan. Gunakan database sementara dan dua pengunjung.

Untuk implementasi, `npm run check` harus lolos. Gunakan database/port sementara bila
relevan, periksa kembali [PRD](../../PRD.md) dan [aturan proyek](../../AGENTS.md).
Kerjakan tiket ini saja; fitur tiket berikutnya tidak otomatis ikut dikerjakan.
