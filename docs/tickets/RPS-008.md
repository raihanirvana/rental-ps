# RPS-008 — Booking saya, detail dan batal

Status: **Selesai**

Prioritas: **P0**

Dependensi: RPS-007

## Tujuan dan cakupan

Bangun daftar booking pengunjung, detail snapshot dan pembatalan. Pisahkan data contoh
owner dari booking yang dibuat pengunjung, termasuk setelah role switch.

## Kriteria penerimaan

- [x] Daftar menampilkan nomor, unit, interval WIB, durasi, nilai dan status.
- [x] Mendatang, riwayat dan dibatalkan mudah ditemukan; pagination/filter tidak
  menampilkan label halaman baru dengan baris lama selama memuat.
- [x] Detail selalu dibaca dari API dan memakai snapshot, bukan katalog terbaru.
- [x] Customer tidak melihat seed atau booking workspace lain melalui URL langsung.
- [x] Batal menampilkan konfirmasi; dibatalkan di dialog tidak mengubah data.
- [x] Berhasil batal memperbarui daftar/detail dan slot. Larangan setelah mulai
  dari server ditampilkan jelas tanpa merusak state sebelumnya.
- [x] Respons lambat, kosong, 404, error/retry dan sesi habis ditangani.
- [x] Tab baru/refresh tetap menemukan booking saat sesi/database masih berlaku.
- [x] Tidak menyebut reservasi sebagai bukti pembayaran atau struk lunas.

## Verifikasi tanpa unit test

Buat booking, ganti nama/tarif unit lewat data sementara dan pastikan detail lama tetap.
Periksa daftar kosong, paging, batal sebelum mulai, penolakan sesudah mulai, seed, role
switch, URL asing dan kegagalan fetch. Uji keyboard serta layout ponsel pada build produksi.

Untuk implementasi, `npm run check` harus lolos. Gunakan database/port sementara bila
relevan, periksa kembali [PRD](../../PRD.md) dan [aturan proyek](../../AGENTS.md).
Kerjakan tiket ini saja; fitur tiket berikutnya tidak otomatis ikut dikerjakan.

### Perubahan

- `/booking-saya` (`pages/MyBookingsPage.jsx`, `components/my-bookings/*`): tab Mendatang,
  Riwayat, Dibatalkan (view server `upcoming`/`finished`/`cancelled`), paginasi 10/halaman,
  tab/halaman di URL. Item: nomor, status teks (Mendatang/Sedang main/Sudah berakhir/
  Selesai/Dibatalkan), unit snapshot, tanggal + jam WIB, durasi, nilai reservasi.
- `/booking-saya/:id` (`pages/BookingDetailPage.jsx`): detail dari `GET /api/bookings/:id`
  (snapshot unit/tarif/nilai), info pembatalan, "Pembayaran dilakukan di tempat. Aplikasi
  tidak mencatat pembayaran." 404 server → "Booking tidak ditemukan." dengan teks yang sama
  untuk seed, workspace lain dan ID asing.
- Pembatalan: dialog konfirmasi + alasan opsional (≤200, tanpa karakter kontrol). Kembali/
  Escape tidak mengirim apa pun. Sukses → detail diganti respons server + notice "Jam … tersedia
  lagi". 409/404 → dialog ditutup, pesan server ditampilkan, detail dimuat ulang di latar
  tanpa mengosongkan tampilan. Error jaringan/503 tetap di dialog untuk dicoba lagi.
- `lib/load-resource.js`: request lama di-abort dan responsnya diabaikan; daftar tidak
  menampilkan baris lama selama key (tab/halaman) baru dimuat; label halaman dari data server.
- Rute berparameter di `lib/routes.js` (menu aktif tetap "Booking saya" di halaman detail).
- **Perbaikan server (RPS-001):** fallback SPA `app.get('/{*path}')` mengembalikan 500 untuk
  path dengan encoding rusak (`/booking-saya/%E0%A4%A`, `/x/%ZZ`). Diganti middleware GET/HEAD
  tanpa parameter rute: 200 index.html (404 React), API tetap 404 JSON, log bersih.

### Temuan dan perbaikan selama uji

- Perubahan rute berparameter sempat membuat `/` jatuh ke 404 (segmen kosong ditolak untuk
  segmen statis). Diperbaiki dan dicek untuk `/`, `/booking-saya/`, ID, path rusak dan path asing.
- Rencana awal memuat ulang detail lewat `retry()` setelah pembatalan ditolak akan
  mengosongkan tampilan dan notice; diganti `refresh()` di latar sebelum diuji.
- Fallback SPA server 500 untuk path rusak (lihat Perubahan).

### Batasan

- Booking berlangsung dibuat langsung di DB karena tidak bisa dipesan lewat API (lead time).
- Penolakan pembatalan di UI diuji dengan 409 yang diinjeksi; penolakan server nyata dibuktikan
  lewat POST langsung pada booking berlangsung.
- Paginasi limit/offset dapat bergeser bila data berubah di antara halaman (batas API RPS-005).
- Hanya Chromium; Firefox/Safari dan pembaca layar sungguhan belum diuji.
