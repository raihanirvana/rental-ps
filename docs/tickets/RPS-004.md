# RPS-004 — Katalog dan mesin ketersediaan slot

Status: **Selesai**

Prioritas: **P0**

Dependensi: RPS-003

## Tujuan dan cakupan

Implementasikan GET catalog dan GET availability. Katalog anonim memakai data publik
read-only; sesi memakai unit workspace sendiri. Slot dihitung server menurut WIB dan PRD.

## Kriteria penerimaan

- [x] Membaca katalog anonim tidak membuat workspace atau cookie sesi.
- [x] Availability memerlukan sesi; tidak membuka nama/nomor pelanggan atau booking asing.
- [x] Tanggal hari ini sampai D+14 inklusif, jam 10.00–23.00, grid 30 menit,
  durasi 60/120/180 menit dan lead time 15 menit dihitung dari waktu server.
- [x] Tanggal invalid, format ambigu, durasi asing dan ID unit tidak valid ditolak.
- [x] Unit nonaktif tidak dapat dipesan. Unit asing mengembalikan 404.
- [x] Interval [mulai, selesai) mencakup overlap sebagian; sesi bersebelahan diperbolehkan.
- [x] Booking non-cancelled dan blok menutup slot; cancelled tidak menutupnya.
- [x] Respons menyertakan waktu server, tarif/quote dan alasan slot tidak tersedia,
  tanpa menyiratkan slot sedang ditahan.
- [x] Ketersediaan tidak berubah karena zona waktu perangkat browser.

## Verifikasi tanpa unit test

Gunakan D+1 dan unit sementara. Periksa overlap 19.00–21.00 dengan 20.30, slot 21.00,
unit berbeda, blok, cancelled, unit nonaktif, batas 22.30 dan tanggal tidak valid.
Pastikan jumlah workspace tidak berubah setelah banyak GET publik.

Untuk implementasi, `npm run check` harus lolos. Gunakan database/port sementara bila
relevan, periksa kembali [PRD](../../PRD.md) dan [aturan proyek](../../AGENTS.md).
Kerjakan tiket ini saja; fitur tiket berikutnya tidak otomatis ikut dikerjakan.

## Bukti penyelesaian

Diverifikasi 15 Oktober 2026 ±15.57 WIB (D = 2026-10-15) dengan database sementara di
scratchpad dan port 4347/4348; server uji dihentikan lewat PID sendiri. `npm run check` lolos.

### Perubahan

- `GET /api/catalog`: tanpa sesi (atau cookie tidak valid) → contoh publik statis
  `source: "sample"`, unit `id: null`, tanpa membaca/membuat workspace atau Set-Cookie.
  Dengan sesi → `source: "workspace"`, pengaturan dan unit workspace sendiri (termasuk
  `isActive`). Keduanya memuat `rules` jadwal.
- `GET /api/availability?unitId=&date=&durationMinutes=` (perlu sesi customer/owner):
  slot grid 30 menit 10.00–23.00 WIB, `available` + `reason`
  (`unit_inactive`, `past`, `lead_time`, `blocked`, `booked`), `quote` (tarif × durasi),
  `serverTime`, `serverDate`, `timeZone`, `bookableDates` dan `notice` bahwa slot tidak ditahan.
- `server/lib/schedule.js` (grid, horizon D…D+14, `[mulai, selesai)`, alasan slot; dipakai lagi
  untuk validasi booking RPS-005), `schedule-rules.js`, `money.js`, `wib-time.js`
  (`isValidDateKey` ketat, `wibTimeLabel` via `Intl` zona Asia/Jakarta).
- Validasi query: allowlist `unitId`/`date`/`durationMinutes`, nilai tunggal, tanggal kalender
  nyata, durasi persis `60|120|180`. Tanggal di luar horizon → 400 `DATE_OUT_OF_RANGE`.
- Repository baca: unit per workspace, interval booking non-cancelled dan blok (hanya
  `starts_at/ends_at`, tanpa data pelanggan), pengaturan usaha. Dibaca dalam satu read transaction.

### Batasan

- Booking, blok dan unit nonaktif dibuat langsung di database sementara karena POST
  booking (RPS-005) dan pengelolaan unit/blok (RPS-010) belum ada.
- Uji zona waktu dilakukan dengan mengubah `TZ` proses server; client belum ada, tetapi
  client hanya akan menampilkan label WIB dari server (RPS-007).
- Katalog publik tidak di-cache (seluruh `/api` `no-store`), cukup untuk demo.
