# RPS-013 — Deployment gratis dan panduan presentasi

Status: **Selesai**

Prioritas: **P1**

Dependensi: RPS-012

## Tujuan dan cakupan

Siapkan satu Node Web Service untuk frontend/API, dokumentasi dan konfigurasi deployment.
Target awal Render Free; verifikasi ketersediaan paket/kuota/runtime pada saat pelaksanaan.
Tiket belum selesai hanya karena file konfigurasi hosting sudah dibuat.

## Kriteria penerimaan

- [x] Pilihan hosting gratis dan batas akun diperiksa; tidak membuat layanan/disk berbayar.
- [x] Runtime mendukung node:sqlite; build/start, PORT, bind address dan NODE_ENV benar.
  SQLite memakai storage sementara dengan batas yang dinyatakan jelas.
- [x] Secret lewat environment hosting, bukan Git; trust proxy disesuaikan dan diuji nyata.
- [x] URL HTTPS publik memuat landing, deep link dan API pada satu origin.
- [x] Cookie Secure, sesi, booking, konflik slot dan dua pengunjung diverifikasi live.
- [x] Setelah kehilangan database, UI menawarkan demo baru tanpa loop/error yang menyesatkan.
- [x] README mencantumkan URL, langkah deploy/redeploy, konfigurasi, batas sleep/kuota,
  kemungkinan kehilangan data dan cara memulihkan demo.
- [x] Ada panduan presentasi singkat: booking pelanggan → agenda owner → konflik → reset.
- [x] Jika kuota/otorisasi/deploy platform menghalangi, catat blocker dan status belum selesai;
  jangan mengklaim live atau otomatis beralih ke paket berbayar.

## Verifikasi tanpa unit test

Periksa URL publik dari browser dan curl, lakukan booking D+1, replay key, role switch,
workspace kedua dan reset. Periksa header HTTPS dan refresh deep link. Verifikasi restart
hanya pada service demo yang dibuat untuk proyek ini; jangan mengganggu service POS.

Untuk implementasi, `npm run check` harus lolos. Gunakan database/port sementara bila
relevan, periksa kembali [PRD](../../PRD.md) dan [aturan proyek](../../AGENTS.md).
Kerjakan tiket ini saja; fitur tiket berikutnya tidak otomatis ikut dikerjakan.

### Perubahan dan hosting

- `render.yaml` dan `scripts/deploy-render.sh`: satu Free Web Service Singapore, tanpa
  persistent disk/database berbayar; build `npm ci --include=dev && npm run check`, start
  `npm start`, health `/api/health`. `HOST=0.0.0.0`, PORT Render **10000**, production.
- Node dipin **22.20.0** di hosting; engine package/lock `>=22.13.0 <23`. Migrasi otomatis
  dan SQLite berjalan nyata di runtime hosting. `TRUST_PROXY=1`, origin tambahan kosong.
- Service `srv-db8g31rncjis73auevmg`, repo rental-ps/master, paket **free**, satu instance.
  CLI terotorisasi yang sudah ada dipakai; tidak menyimpan token/.env/SQLite di Git.
- Auto-deploy **off**. Push disusul script redeploy agar perubahan dokumentasi tidak
  menghapus ruang demo saat presentasi. Blueprint dan create CLI memakai konfigurasi sama.
- Script menolak `RENDER_SERVICE_ID` milik POS dan create duplikat (keduanya diuji, exit 1,
  tanpa mutasi). Script tidak mengubah plan, limit billing atau service lain.
- [Panduan deployment/presentasi](../DEPLOYMENT.md) menjelaskan alur, pemulihan dan kuota.

### Bukti URL publik

- Curl HTTPS `/api/health`: 200, `database: connected`, HSTS, CSP, nosniff, anti-iframe,
  `Cache-Control: no-store`. HTTP dialihkan ke HTTPS.
- Login: 201; cookie **Secure; HttpOnly; SameSite=Strict; Path=/api**. Header proxy palsu
  `X-Forwarded-Proto: http`/`X-Forwarded-Host: evil.example` tidak menurunkan Secure/HSTS.
  Origin asing (termasuk dengan proxy host palsu) ditolak 403; customer ke owner 403.
- D+1 **16 Oktober, PS5 A 19.00–21.00**: 201, Rp50.000. Replay key/payload sama: 200
  dengan ID sama; interval 20.30–21.30: 409 `SLOT_UNAVAILABLE`.
- Pengunjung kedua mendapat ID unit berbeda, slot tadi masih kosong, daftar personal 0,
  detail booking A mendapat 404, dan dapat memesan slot sama di ruangnya sendiri.
- Ganti owner: data dan TTL tetap, cookie lama 401, booking terlihat di agenda. Reset A
  menghapus booking A; booking B tetap 200. Workspace uji API dibersihkan lewat logout.
- Landing dan lima deep link: 200 HTML React. API tidak dikenal: 404 JSON.
- **Chrome headless** nyata: landing anonim tanpa cookie → booking → konfirmasi → history
  (tetap ada setelah refresh) → ganti owner → agenda D+1 → pengaturan/deep-link refresh →
  reset. Cookie HTTPS browser diperiksa; tidak ada page exception/pelanggaran CSP.
- **Restart nyata hanya service sesi-play**: cookie owner sebelum restart mendapat 401;
  halaman pengaturan stabil menawarkan mulai demo, satu klik membuat ruang owner baru
  dengan ID unit baru, lalu refresh tetap berhasil. Tidak ada loop atau exception/CSP.
  Service POS dan be-report-keuangan tidak di-restart/diubah.
